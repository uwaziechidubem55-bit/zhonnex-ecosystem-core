# Zhonnex Foundry — ninth software, first core prototype

A demand-first digital product builder. Users describe digital ideas, search public requests and discuss solutions. The owner can generate a **static website starter**. Other digital kinds are accepted as briefs, but generation of apps, software and other products is **not yet implemented**. Verified real builders may be listed; project owners pay a one-time access fee before contacting them. Prices are NGN integer kobo; future-value ranges are hypothetical scenarios, not financial predictions or fixed prices.

`index.ts` is a domain prototype with **in-memory state**. It is not an HTTP server, payment processor, public marketplace, database, VM, or terminal. The `recordBuilderAccessPayment` method must be callable only by a trusted server after independently checking Paystack signature and transaction reference, amount, currency, buyer, status and replay against a transactional database; its `verifiedByServer` field is not proof if accepted from a browser. `verifyBuilder` is an admin-only operation; an HTTP API must enforce that. Never expose direct builder contact details through public listing.

Before public launch: identity/authentication, moderation and abuse controls, real builder verification and consent, durable transactional storage, verified payment/webhook integration, buyer-builder messaging, dispute/refund terms, real code-generation workflows with review, and isolated resource-limited runtime infrastructure. **Never run user code on the host or give a public terminal direct access to the backend.** Hosting arbitrary projects requires per-project isolation, budgets, outbound-network policy, scanning, logs, and an operator-approved deployment pipeline. No claim is made that Foundry can generate every digital product or guarantee future value.

Test (with Node typings and TypeScript): compile `index.ts` and `foundry.test.ts` to CommonJS, then run the emitted test. No secret keys are included.
